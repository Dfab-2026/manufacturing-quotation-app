# V74 — Manual RFQ workbook integration

Base: V73. No new libraries required. Uploaded workbook used locally; the original is preserved unchanged in backend/private_reference. JSON contains cached values, explicit/shared formula metadata and historical drawing-indexed populated rows. 58 distinct drawing numbers; nine sheets, Summary and Standard Parts List have no cell values. Blank formula templates excluded. Original workbook retains all data including drawings, links, and formatting. This is deterministic rules + reference retrieval, NOT neural model fine-tuning or validated supervised training.

Rates: existing unedited built-in starters migrate only when price, unit and starter note match. Custom/approved rates stay unchanged. New installations use workbook-derived defaults. Fresh settings markup 40%, existing user settings preserved. Workbook does not justify resetting existing wastage or overhead. Incompatible unit changes on rate refresh keep prior row unchanged and mark review (re-analyze for new costing). Rate notes cite the sheet/columns. Unspecified stainless and Al/Mg rates are selectable, not globally assigned to specific alloys. Manual laser cost uses normalized explicit cutting length (mm converted to m), thickness and piercing count, quantity. Missing length uses existing job estimate; exact developed cutting path not implemented. Generic measured welding uses common 18/inch; alternative 20/35 available, weld passes/joints need review. TIG/MIG rates are not inferred from workbook ambiguous categories. Manual stretch wrap rate selectable. No reliable positive rates for several finish methods or purchased components in the sheet; retain existing fallback/manual review. Existing separate labour allowances may require review to avoid double counting with manual process rates. Historical totals contain possible doubled material quantities and mixed cutting length units; no blind import of totals, no automatic reuse of historical geometry. Exact drawing number history appears in drawing notes when the private reference is present.

If deploying on Render, arrange private data provisioning independently; rate code remains available without the private reference, historical matches will not. No actual deployment performed.
